# 五、踩坑与经验总结

## 1. RAG 侧

| 坑 | 正确做法 |
|----|----------|
| 切分粒度拍脑袋 | 固定长度切分容易打断语义，生产环境优先递归切分 |
| 召回不准就换模型 | 先查切分和 Prompt，不要第一反应就换模型 |
| 建库和查询用不同嵌入模型 | 建库和查询必须用同一个嵌入模型，换模型必须重建索引 |
| 元数据随便写 | `parent_id`、来源、版本必须写入向量库 |

---

## 2. Agent 侧

| 坑 | 正确做法 |
|----|----------|
| 以为模型能执行代码 | 模型不执行代码，只返回 tool_calls；真正执行在宿主程序 |
| 以为 ReAct 一次成型 | 每一轮都要判断 Observation 是否足够，不够就继续循环 |
| 没有审计和拦截 | Middleware 是生产级 Agent 的分界线：没有拦截与审计，工具调用就是黑盒 |

---

## 3. 工程与部署

- 密钥绝不进代码，`.env` + `.gitignore` 是底线。
- 请求必须设超时、重试和错误日志，客户端对象应复用。
- Demo 向量库用 Chroma，生产环境优先考虑 Milvus / pgvector。
